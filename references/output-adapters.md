# Output Adapters — Per-Tool Entry Files

Different AI agents auto-load different files at session start. ICM keeps ONE source of
truth (`AGENTS.md`) and generates a **full copy** for each tool the team uses, so every
agent gets the complete context natively — no stubs, no "go read another file" hop.

Drift is prevented by process, not by stubs: every copy carries a GENERATED header, and
UPDATE mode always regenerates every copy from AGENTS.md.

## The generation rule

For each target tool, write a file whose content is:

1. The GENERATED header (below), then
2. The complete content of `AGENTS.md`, verbatim (including the `<!-- icm:managed -->`
   marker), then
3. The tool-specific footer (only where the table below defines one)

GENERATED header (exact text, fill the date):

```markdown
<!-- GENERATED from AGENTS.md by icm-builder on [YYYY-MM-DD]. Do NOT edit this file.
     Edit AGENTS.md, then re-run icm-builder in UPDATE mode to regenerate all copies. -->
```

## Target files by tool

| Tool | File | Notes |
|------|------|-------|
| OpenCode, Codex, Jules, Amp, Zed | `AGENTS.md` | Native — this IS the source file. No copy. |
| Claude Code | `CLAUDE.md` | Full copy at repo root. |
| Gemini CLI | `GEMINI.md` | Full copy at repo root. |
| Cursor | `.cursor/rules/icm.mdc` | Full copy WITH the MDC frontmatter below prepended before the GENERATED header. |
| GitHub Copilot | `.github/copilot-instructions.md` | Full copy. |
| Windsurf | `.windsurfrules` | Full copy. |

Cursor MDC frontmatter (required for the rule to always apply):

```markdown
---
description: Project context — ICM workspace (generated from AGENTS.md)
alwaysApply: true
---
```

## Which copies to generate

Ask the user in Phase 3 which agents their team uses; generate only those copies plus
`AGENTS.md` itself. If the user says "all" or is publishing the repo publicly, generate
Claude Code, Gemini CLI, Cursor, and Copilot copies by default.

If a tool file already exists (e.g., a hand-written `CLAUDE.md`):

- If it has the GENERATED header → overwrite freely.
- If it does not → show the user a diff of what would be lost and ask before replacing.
  Offer to merge their hand-written content into `AGENTS.md` first so nothing is lost.

## Tool-specific config beyond the entry file

| Tool | Extra config ICM may generate |
|------|-------------------------------|
| Claude Code | `.mcp.json` (MCP servers), `.claude/settings.json` (hooks), `.claude/skills/`, `.claude/agents/` |
| OpenCode | `opencode.json` (`mcp` block, permissions), `.opencode/skill/`, `.opencode/agent/` |
| Cursor | `.cursor/mcp.json` (MCP servers) |
| Gemini CLI | `.gemini/settings.json` (`mcpServers` block) |

Generate these only when the corresponding phase (7) confirmed the need, and label each
with the tool it belongs to in the delivery output.

## Verification after generation

For each generated copy, confirm:

- [ ] First line is the GENERATED header
- [ ] Content after the header is byte-identical to AGENTS.md (plus allowed frontmatter/footer)
- [ ] `.cursor/rules/icm.mdc` has `alwaysApply: true`
- [ ] `.icm/manifest.md` lists every copy under "Tools configured for"
